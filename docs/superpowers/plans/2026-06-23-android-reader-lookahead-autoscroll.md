# Android Reader lookahead pin-to-top auto-scroll — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the shipped iOS vertical-mode lookahead pin-to-top auto-scroll to the Folino **Android** Reader — same behavior: during playback, pin the playing cursor's system to the top of the viewport (cleared below the top bar), triggered ~2 beats ahead, re-scrolling only when the lookahead or playing system leaves the viewport.

**Architecture:** Reuse the shared logic via two JNI bridges (parity — no Kotlin re-port of notation/scroll math). **Bridge A** exposes ssm `Score.cursor(advancedByBeats:from:)` to Kotlin (`SheetMusicAndroidJNI` Swift + `SheetMusicJNI.kt` facade → mavenLocal AAR). **Bridge B** exposes Folino `Domain.scrollOffsetPinningSystemTop` to Kotlin (`FolinoReaderJNI` → staged `.so` + jextract binding). Android-specific glue is Kotlin only: `ReaderAudioViewModel` computes a `scrollAnchorCursor` StateFlow (while playing), and `ReadyScore`'s scroll `LaunchedEffect` pins the playing system to the top using both cursors. The iOS Domain function `scrollOffsetPinningSystemTop` and ssm `cursor(advancedByBeats:)` already exist on `main`.

**Tech Stack:** Kotlin / Jetpack Compose (Android Reader), Swift JNI via swift-java jextract, swift-sheet-music ("ssm") Android AARs via Gradle `mavenLocal()`, Swift 6.3.2 Android cross-compile toolchain, Android emulator.

**Spec:** `docs/superpowers/specs/2026-06-22-reader-vertical-lookahead-autoscroll-design.md` (iOS; this plan is its Android parity follow-up, noted under "Parity follow-up").

## Global Constraints

- **Parity:** match iOS behavior exactly and SHARE logic. Notation (`cursor(advancedByBeats:)`) and scroll math (`scrollOffsetPinningSystemTop`) are bridged from Swift, NOT re-ported to Kotlin. Only the lookahead-anchor glue + Compose scroll wiring are Android-specific.
- **Vertical mode only.** Horizontal / Page modes unchanged.
- **Lead = 2 quarter-note beats.** Kotlin constant `SCROLL_LOOKAHEAD_BEATS = 2.0`.
- **Lookahead active only while playing.** Not playing → no anchor → fall back to today's `nativeScrollOffsetKeepingInView`.
- **Pin clearance:** the Android score viewport sits INSIDE the Scaffold content padding (below the `ReaderTopBar`), so the pin `topInset` = the existing `vPadPx` (16.dp) breathing room — no top-bar-height term needed.
- **ssm Android consumption:** Folino Android pulls `io.github.jiyimeta:sheet-music-{android,audio-android,compose-android}:$ssmVersion` from `mavenLocal()`; default `ssmVersion=0.0.0-SNAPSHOT` (`Android/gradle.properties`). During dev use a branch-suffixed version + `-PssmVersion=0.0.0-android-lookahead-SNAPSHOT` to avoid colliding the shared SNAPSHOT slot; republish to the default slot at the end.
- **Android cross-compile toolchain:** the `.so` build scripts need the Swift 6.3.2 Android SDK + NDK. Prefix with `PATH=/Library/Developer/Toolchains/swift-6.3.2-RELEASE.xctoolchain/usr/bin:$PATH` per the project's Android-build convention; a fresh ssm worktree rebuilds all `.so` (jextract bindings regenerated by the build scripts).
- **Android changes are verified by install+launch on the emulator** (`ANDROID_SERIAL=emulator-5554`, `:app:installDebug`, `adb shell am start`), not by unit tests — the shared logic is already unit-tested on iOS.
- **ssm push is gated** (human confirm) and happens at the END (the Android build consumes the local mavenLocal AAR, not a pushed revision). Folino **iOS** does NOT need re-pinning (the bridge is Android-only; the iOS-consumed `cursor(advancedByBeats:)` is already at the pinned ssm revision `3f7884d7`).
- Two repos: ssm `~/Developer/Personal/swift-packages/swift-sheet-music` (worktree off ssm `main` 3f7884d7); Folino `~/Developer/Personal/ios-apps/Folino-iOS` (worktree off local `main` e0764804).

```swift
import Foundation
import SheetMusicCore

/// JNI entry point for Kotlin `SheetMusicJNI.nativeCursorAdvancedByBeats(...)`. Advances `fromCursorBytes` by
/// `beats` quarter-note beats via the shared `Score.cursor(advancedByBeats:from:)` (deterministic notation math)
/// and returns the result as a `ScoreCursorCodec` payload. Returns `fromCursorBytes` unchanged when the handle is
/// unknown or the input cursor can't be decoded — identical failure mode to `nativeStepMeasureCursor`.
public func nativeCursorAdvancedByBeats(
    scoreHandle: Int64,
    fromCursorBytes: Data,
    beats: Double,
) -> Data {
    guard let score = scoreTable.value(for: scoreHandle),
          let from = try? ScoreCursorCodec.decode(fromCursorBytes)
    else { return fromCursorBytes }
    let target = score.cursor(advancedByBeats: beats, from: from)
    return ScoreCursorCodec.encode(target)
}
```

- [ ] **Step 1: Add the lookahead anchor StateFlow**

Add to `ReaderAudioViewModel`, mirroring how `currentCursor` (lines ~75-77) is derived from `_engine`. Use the VM's existing engine-state flow and `scoreHandle` property:

```kotlin
/**
 * Lookahead anchor for vertical-mode auto-scroll: the cursor [SCROLL_LOOKAHEAD_BEATS] quarter-note
 * beats ahead of the live cursor, via the shared ssm `Score.cursor(advancedByBeats:from:)` (JNI).
 * Non-null ONLY while playing; the Reader falls back to keep-in-view when null. Mirrors iOS
 * `ReaderPlaybackSession.scrollAnchorCursor`.
 */
val scrollAnchorCursor: StateFlow<ScoreCursor?> =
    _engine.flatMapLatest { engine ->
        if (engine == null) flowOf(null)
        else combine(engine.state, engine.currentCursor) { state, cursor ->
            val handle = scoreHandle
            if (state != PlaybackState.PLAYING || cursor == null || handle == null) {
                null
            } else {
                ScoreCursorCodec.decode(
                    SheetMusicJNI.nativeCursorAdvancedByBeats(
                        handle, ScoreCursorCodec.encode(cursor), SCROLL_LOOKAHEAD_BEATS,
                    ),
                )
            }
        }
    }.stateIn(viewModelScope, SharingStarted.Eagerly, null)
```


- [ ] **Step 1: Rewrite the vertical auto-scroll to pin-to-top**

Replace the body of the auto-scroll `LaunchedEffect` so it combines the real cursor + the lookahead anchor, pins the playing system to the top during playback, and falls back to keep-in-view otherwise. Keep the existing horizontal-scroll block unchanged (it follows the real cursor). Match the existing file's exact `Double`/`Float` conversions and frame field names:

```kotlin
LaunchedEffect(scoreHandle, fitPxPerMM, scale) {
    val handle = scoreHandle ?: return@LaunchedEffect
    if (fitPxPerMM <= 0f) return@LaunchedEffect
    combine(audioVm.currentCursor, audioVm.scrollAnchorCursor) { real, anchor -> real to anchor }
        .collectLatest { (real, anchor) ->
            if (real == null) return@collectLatest
            val realBytes = SheetMusicJNI.nativeCursorFrame(handle, ScoreCursorCodec.encode(real))
            if (realBytes.isEmpty()) return@collectLatest
            val realFrame = DecodedFrameCodec.decode(realBytes)
            val realYMin = (vPadPx + realFrame.y * fitPxPerMM * scale).toDouble()
            val realYMax = (vPadPx + (realFrame.y + realFrame.height) * fitPxPerMM * scale).toDouble()

            val newY = if (anchor != null) {
                // Playing: pin the playing system to the top, triggered by the lookahead/playing system
                // leaving the viewport. topInset = vPadPx clears the (already-inset) top bar.
                val anchorBytes = SheetMusicJNI.nativeCursorFrame(handle, ScoreCursorCodec.encode(anchor))
                val lookaheadYMax = if (anchorBytes.isNotEmpty()) {
                    val af = DecodedFrameCodec.decode(anchorBytes)
                    (vPadPx + (af.y + af.height) * fitPxPerMM * scale).toDouble()
                } else {
                    realYMax
                }
                FolinoReaderJNI.nativeScrollOffsetPinningSystemTop(
                    vScroll.value.toDouble(),
                    realYMin,
                    realYMax,
                    lookaheadYMax,
                    viewportSize.height.toDouble(),
                    vPadPx.toDouble(),
                ).toFloat()
            } else {
                // Paused / manual seek: gentle keep-in-view (today's behavior).
                FolinoReaderJNI.nativeScrollOffsetKeepingInView(
                    vScroll.value.toDouble(),
                    realYMin,
                    realYMax,
                    viewportSize.height.toDouble(),
                    padPx.toDouble(),
                ).toFloat()
            }
            if (abs(newY - vScroll.value) >= 0.5f) {
                vScroll.animateScrollTo(newY.toInt().coerceAtLeast(0))
            }
            // (Leave the existing horizontal-scroll-when-zoomed block below, following `real`.)
        }
}
```
