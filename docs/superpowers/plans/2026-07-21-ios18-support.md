## Task 1 — Compat helpers in UtilityUI

Create `Packages/Utility/Sources/UtilityUI/GlassEffectCompat.swift` with public `View` extensions:

- `interactiveGlassCompat()` → 26: `glassEffect(.regular.interactive())`; 18: `background(.regularMaterial, in: Capsule())`
- `interactiveGlassCompat<S: Shape>(in: S)` → 26: `glassEffect(.regular.interactive(), in: shape)`; 18: `background(.regularMaterial, in: shape)`
- `regularGlassCompat<S: Shape>(in: S)` → 26: `glassEffect(.regular, in: shape)`; 18: `background(.regularMaterial, in: shape)`
- `glassProminentButtonStyleCompat()` → 26: `buttonStyle(.glassProminent)`; 18: `buttonStyle(.borderedProminent)`

All `@ViewBuilder` + `if #available(iOS 26, *)`. iOS-26-only types (`Glass`, `GlassProminentButtonStyle`)
must appear only inside the available branch. Add a `#Preview` exercising each helper.

Verify: `xcodebuild build -scheme UtilityUI …` (package dir) after lowering Utility's platform (Task 3).

## Task 4 — Build to green (availability sweep)

Iterate edit → build until clean. The iOS 26 simulator destination is fine — availability errors come
from the deployment target, not the sim OS.

```
xcodebuild -project Folino.xcodeproj -scheme Folino \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro Max' \
  -skipPackagePluginValidation build
```

Then build the edited package schemes directly (Utility, Reader, Library, ImportExport) to defeat the
app build's increment-skip false SUCCEEDED. Any newly-surfaced iOS 26 API → guard it the same way.
